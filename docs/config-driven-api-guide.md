# Config-Driven API System Guide

## Overview

The config-driven API system allows you to create **fully functional REST APIs without writing TypeScript code**. Everything - from simple CRUD operations to complex multi-step workflows with conditionals, loops, and validations - is defined in JSON configuration files.

## Key Benefits

- ✅ **No code generation** - APIs are interpreted at runtime
- ✅ **Complex logic support** - Conditionals, loops, validations, transactions
- ✅ **Type-safe** - Validated against JSON Schema format
- ✅ **Hot-reload friendly** - Change configs without recompiling
- ✅ **Consistent patterns** - Same approach as config-driven pages
- ✅ **AI-compatible** - Easily generated by AI from natural language

## Architecture

```
config/api/*.json          → API configs (your definitions)
     ↓
src/api/config-loader.ts   → Discovers and loads configs
     ↓
src/api/engine/route-engine.ts → Generates Hono routes
     ↓
src/api/engine/workflow-engine.ts → Executes workflow steps
     ↓
src/api/engine/expression-evaluator.ts → Evaluates conditions safely
```

## Quick Start

### 1. Create an API Config

Create `config/api/tasks.json`:

```json
{
  "resource": "tasks",
  "basePath": "/api/tasks",
  "description": "Task management API",
  "table": "tasks",
  "auth": {
    "required": true
  },
  "operations": {
    "list": { "enabled": true },
    "getById": { "enabled": true },
    "create": { "enabled": true },
    "update": { "enabled": true },
    "delete": { "enabled": true }
  }
}
```

### 2. Restart Server

```bash
npm run dev
```

### 3. Use Your API

```bash
# List tasks
GET /api/tasks

# Get task by ID
GET /api/tasks/:id

# Create task
POST /api/tasks
{"title": "Buy groceries", "status": "pending"}

# Update task
PUT /api/tasks/:id
{"status": "completed"}

# Delete task
DELETE /api/tasks/:id
```

That's it! You now have a fully functional CRUD API.

## Configuration Reference

### Basic Structure

```json
{
  "resource": "string",      // Resource name
  "basePath": "string",       // API path (e.g., "/api/tasks")
  "description": "string",    // Optional description
  "table": "string",          // Database table name
  "auth": {                   // Authentication config
    "required": boolean,
    "permissions": ["string"]
  },
  "operations": {             // CRUD operations
    "list": {...},
    "getById": {...},
    "create": {...},
    "update": {...},
    "delete": {...},
    "custom": [...]           // Custom endpoints
  }
}
```

### List Operation

Supports filtering, searching, sorting, and pagination:

```json
{
  "list": {
    "enabled": true,
    "filters": [
      {
        "field": "status",
        "operator": "equals",
        "queryParam": "status"
      }
    ],
    "search": {
      "enabled": true,
      "fields": ["title", "description"]
    },
    "sort": {
      "default": "createdAt",
      "defaultOrder": "desc",
      "allowed": ["createdAt", "title", "status"]
    },
    "pagination": {
      "enabled": true,
      "defaultLimit": 50,
      "maxLimit": 100
    }
  }
}
```

**Usage:**
- `GET /api/tasks?status=pending` - Filter by status
- `GET /api/tasks?search=groceries` - Search in title/description
- `GET /api/tasks?sortBy=title&sortOrder=asc` - Sort by title
- `GET /api/tasks?limit=20&offset=0` - Paginate results

### Create Operation

Supports validation and defaults:

```json
{
  "create": {
    "enabled": true,
    "validation": {
      "required": ["title"],
      "fields": {
        "title": {
          "type": "string",
          "min": 1,
          "max": 255
        },
        "status": {
          "type": "string",
          "enum": ["pending", "in_progress", "completed"]
        },
        "priority": {
          "type": "number",
          "min": 1,
          "max": 5
        },
        "email": {
          "type": "email"
        }
      }
    },
    "defaults": {
      "status": "pending",
      "priority": 3
    }
  }
}
```

**Validation Types:**
- `string`, `number`, `boolean`, `email`, `url`, `uuid`, `date`
- `min`, `max` - For length (strings) or value (numbers)
- `pattern` - Regex pattern
- `enum` - Allowed values

### Relations

Load related data automatically:

```json
{
  "getById": {
    "enabled": true,
    "relations": [
      {
        "name": "user",
        "table": "users",
        "foreignKey": "userId",
        "referencedKey": "id",
        "type": "one"
      },
      {
        "name": "comments",
        "table": "comments",
        "foreignKey": "taskId",
        "type": "many"
      }
    ]
  }
}
```

**Result:**
```json
{
  "id": "123",
  "title": "Task",
  "userId": "456",
  "user": {
    "id": "456",
    "name": "John Doe"
  },
  "comments": [
    {"id": "1", "text": "Great!"},
    {"id": "2", "text": "Done!"}
  ]
}
```

### Soft Delete

Configure soft deletes:

```json
{
  "delete": {
    "enabled": true,
    "softDelete": {
      "enabled": true,
      "field": "deletedAt"
    }
  }
}
```

## Workflows

Workflows enable complex multi-step operations with conditionals, loops, and validations.

### Workflow Step Types

| Step Type | Description | Example Use Case |
|-----------|-------------|------------------|
| `db_query` | Database operations (select, insert, update, delete, count) | Fetch data, create records |
| `check_exists` | Check if record exists | Validation, duplicate prevention |
| `conditional` | If-then-else logic | Apply discounts, validate status |
| `foreach` | Loop over array | Process order items, bulk updates |
| `while` | Conditional loop | Retry logic, pagination |
| `set_variable` | Set context variable | Store calculations, intermediate results |
| `transform` | Transform data (map, filter, sum, etc.) | Data aggregation, formatting |
| `http_request` | Call external API | Webhooks, external services |
| `validate` | Validate data | Input validation, business rules |
| `return_response` | Return custom response | Early exit with data |
| `return_error` | Return error | Validation failures, not found |
| `log` | Log message | Debugging, audit trail |
| `db_transaction` | Wrap steps in transaction | Atomic operations |

### Variable Interpolation

Use `{{variable}}` syntax to reference variables:

```json
{
  "where": {
    "id": "{{params.id}}"
  },
  "data": {
    "userId": "{{user.id}}",
    "total": "{{body.amount * 1.1}}",
    "message": "Order #{{orderId}} created"
  }
}
```

**Available Variables:**
- `body` - Request body
- `params` - URL parameters (e.g., `:id`)
- `query` - Query parameters
- `user` - Authenticated user
- `env` - Environment bindings
- Custom variables set by `set_variable` or `storeAs`

### Conditional Logic

#### Simple Condition (String Expression)

```json
{
  "type": "conditional",
  "conditional": {
    "condition": "total > 100 AND user.status == active",
    "then": [
      {"type": "set_variable", "set_variable": {"name": "discount", "value": 0.15}}
    ],
    "else": [
      {"type": "set_variable", "set_variable": {"name": "discount", "value": 0}}
    ]
  }
}
```

**Supported Operators:**
- Comparison: `==`, `!=`, `>`, `<`, `>=`, `<=`
- Logical: `AND`, `OR`, `NOT`
- Math: `+`, `-`, `*`, `/`, `%`

#### Object Condition

```json
{
  "type": "conditional",
  "conditional": {
    "condition": {
      "field": "user.status",
      "operator": "equals",
      "value": "suspended"
    },
    "then": [
      {
        "type": "return_error",
        "return_error": {
          "message": "Account suspended",
          "code": 403
        }
      }
    ]
  }
}
```

**Condition Operators:**
- `equals`, `not_equals`
- `greater_than`, `less_than`, `gte`, `lte`
- `in`, `not_in`
- `contains`, `starts_with`, `ends_with`
- `exists_in_db` - Check if value exists in database

#### If-Elif-Else

```json
{
  "type": "conditional",
  "conditional": {
    "condition": "total > 1000",
    "then": [
      {"type": "set_variable", "set_variable": {"name": "discount", "value": 0.20}}
    ],
    "elif": [
      {
        "condition": "total > 500",
        "then": [
          {"type": "set_variable", "set_variable": {"name": "discount", "value": 0.10}}
        ]
      },
      {
        "condition": "total > 100",
        "then": [
          {"type": "set_variable", "set_variable": {"name": "discount", "value": 0.05}}
        ]
      }
    ],
    "else": [
      {"type": "set_variable", "set_variable": {"name": "discount", "value": 0}}
    ]
  }
}
```

### Loops

#### Foreach Loop

```json
{
  "type": "foreach",
  "foreach": {
    "items": "body.items",
    "as": "item",
    "steps": [
      {
        "type": "check_exists",
        "check_exists": {
          "table": "products",
          "where": {"id": "{{item.productId}}"},
          "onNotExists": "return_error",
          "error": {"message": "Product not found", "code": 404}
        }
      },
      {
        "type": "db_query",
        "db_query": {
          "action": "insert",
          "table": "order_items",
          "data": {
            "orderId": "{{orderId}}",
            "productId": "{{item.productId}}",
            "quantity": "{{item.quantity}}"
          }
        }
      }
    ],
    "collectAs": "results"
  }
}
```

#### While Loop

```json
{
  "type": "while",
  "while": {
    "condition": "retries < 3 AND success == false",
    "maxIterations": 10,
    "steps": [
      {
        "type": "http_request",
        "http_request": {
          "url": "https://api.example.com/process",
          "method": "POST",
          "body": {"data": "{{payload}}"},
          "storeAs": "response"
        }
      },
      {
        "type": "set_variable",
        "set_variable": {
          "name": "retries",
          "value": "{{retries + 1}}"
        }
      }
    ]
  }
}
```

### Database Operations

#### Select

```json
{
  "type": "db_query",
  "db_query": {
    "action": "select",
    "table": "users",
    "where": {"email": "{{body.email}}"},
    "select": ["id", "name", "email"],
    "orderBy": {"field": "createdAt", "order": "desc"},
    "limit": 1,
    "storeAs": "user"
  }
}
```

#### Insert

```json
{
  "type": "db_query",
  "db_query": {
    "action": "insert",
    "table": "orders",
    "data": {
      "id": "{{crypto.randomUUID()}}",
      "userId": "{{user.id}}",
      "total": "{{totalAmount}}",
      "status": "pending"
    },
    "storeAs": "newOrder"
  }
}
```

#### Update

```json
{
  "type": "db_query",
  "db_query": {
    "action": "update",
    "table": "orders",
    "where": {"id": "{{params.id}}"},
    "data": {
      "status": "completed",
      "completedAt": "{{new Date().toISOString()}}"
    },
    "storeAs": "updatedOrder"
  }
}
```

#### Delete

```json
{
  "type": "db_query",
  "db_query": {
    "action": "delete",
    "table": "temp_data",
    "where": {
      "createdAt": {"$lt": "{{thirtyDaysAgo}}"}
    }
  }
}
```

#### Count

```json
{
  "type": "db_query",
  "db_query": {
    "action": "count",
    "table": "users",
    "where": {"status": "active"},
    "storeAs": "activeUserCount"
  }
}
```

```json
    "output": "productIds",
    "operation": "map",
```


## Custom Operations

Create custom endpoints with full workflow support:

```json
{
  "custom": [
    {
      "path": "/:id/complete",
      "method": "POST",
      "description": "Mark task as completed",
      "workflow": {
        "steps": [
          {
            "type": "check_exists",
            "check_exists": {
              "table": "tasks",
              "where": {"id": "{{params.id}}"},
              "onNotExists": "return_error",
              "error": {"message": "Task not found", "code": 404}
            }
          },
          {
            "type": "db_query",
            "db_query": {
              "action": "update",
              "table": "tasks",
              "where": {"id": "{{params.id}}"},
              "data": {
                "status": "completed",
                "completedAt": "{{new Date().toISOString()}}"
              },
              "storeAs": "task"
            }
          },
          {
            "type": "return_response",
            "return_response": {
              "data": "task"
            }
          }
        ]
      }
    }
  ]
}
```

## Lifecycle Hooks

Execute workflows before/after operations:

```json
{
  "create": {
    "beforeExecute": {
      "steps": [
        {
          "type": "validate",
          "validate": {
            "data": "body",
            "rules": {"required": ["title"]}
          }
        },
        {
          "type": "check_exists",
          "check_exists": {
            "table": "tasks",
            "where": {"title": "{{body.title}}"},
            "onExists": "return_error",
            "error": {"message": "Task already exists", "code": 409}
          }
        }
      ]
    },
    "afterExecute": {
      "steps": [
        {
          "type": "http_request",
          "http_request": {
            "url": "https://webhook.site/notify",
            "method": "POST",
            "body": {"event": "task_created", "data": "{{record}}"}
          }
        }
      ]
    }
  }
}
```

## Best Practices

### 1. Security

- Always validate user input
- Check record existence before operations
- Verify user permissions in workflows
- Use auth middleware for sensitive endpoints

### 2. Performance

- Use `select` fields to limit data fetching
- Add proper database indexes
- Limit loop iterations (`maxIterations`)
- Use pagination for large datasets

### 3. Error Handling

- Provide clear error messages
- Include error codes (404, 400, 403, etc.)
- Use `check_exists` for validation
- Set `onError` strategy in workflows

### 4. Maintainability

- Add `description` to operations
- Use meaningful variable names
- Break complex workflows into smaller steps
- Add `log` steps for debugging

## Troubleshooting

### Config not loading

- Check file is in `config/api/` directory
- Ensure `.json` extension
- Validate JSON syntax
- Restart dev server

### Workflow errors

- Check variable names match (`{{varName}}`)
- Verify table/field names in `db_query`
- Review condition syntax
- Check step types are correct

### Performance issues

- Reduce `max_iterations` on loops
- Add pagination to list operations
- Use `select` to limit fields
- Check database indexes

## Migration from Code-Based APIs

### Before (TypeScript)

```typescript
// src/api/routes/tasks.ts (50+ lines of code)
import { Hono } from 'hono';
import { drizzle } from 'drizzle-orm/d1';
import { tasks } from '../../db/schema';

const app = new Hono();

app.get('/', async (c) => {
  const db = drizzle(c.env.DB);
  const status = c.req.query('status');
  // ... more code
});

app.post('/', async (c) => {
  // ... validation, business logic
});

export default app;
```

### After (Config)

```json
{
  "resource": "tasks",
  "basePath": "/api/tasks",
  "table": "tasks",
  "operations": {
    "list": {
      "enabled": true,
      "filters": [{"field": "status", "operator": "equals"}]
    },
    "create": {
      "enabled": true,
      "validation": {"required": ["title"]}
    }
  }
}
```

**Benefits:**
- 90% less code
- No TypeScript knowledge required
- AI-friendly (easily generated)
- Hot-reload without rebuild
- Consistent patterns across all APIs
